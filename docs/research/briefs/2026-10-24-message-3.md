## What is rising

### 44. A verifier for one open-ended domain has been built out of nothing but model-written probes, at a scale of half a million, with no human anywhere in the reward path, and it retires the narrower line this record fell back to yesterday (high confidence, full text through two instruments)

**The paper.** *Hy-Memory-30B-A3B: Attributed Reinforcement Learning
for Long-Term Memory Writing*, Fei, Kang, Zheng, He and Yu, submitted
15 October 2026 [E109]. It is the technical report behind the open
weights the tenth run reported as part of finding 40, and no run of
this seat has opened it. A grep of every committed file under `docs/`,
`prompts/` and `skills/` on this branch returns the model name only in
the tenth run's own brief, and a pull request search returns nothing,
so this is unreported here rather than re-filed [E113].

**What it does.** It trains a 30B-A3B mixture-of-experts model to
perform the write path of an external memory system, meaning the
decision about what to retain and how to update what is already stored.
The abstract's result, verbatim: "On fixed 20% benchmark subsamples,
Hy-Memory-30B-A3B ranks first on all four evaluated harnesses,
including held-out EverMemOS, with a 55.49% macro average versus 54.62%
for Claude Opus 5" [E109].

**Why it reaches this company, and it is not the benchmark number.**
Two of its section titles are Ursa Minor's own two premises, written by
somebody else. Section 2.3 is "Why ordinary outcome-only RL is
insufficient" and section 5.1 is "Why benchmark questions are not
enough" [E110]. Section 5.1's own sentences state the problem this
repository states: "An unasked write receives no evidence, and a failed
answer does not identify whether the cause was omission, bad wording,
stale-state confusion, retrieval failure, or reader failure" [E110].
That is the sparse-and-unattributable reward problem, named by a model
provider, in a published paper with weights.

**What they did about it is the finding.** They did not buy a signal
and they did not hire graders. They manufactured the verifier. The
reward artifact, from the paper's own figure 2 and section 5.7
[E110]: 12,671 windows over 57,616 chunks, 164,576 positive probes,
8,599 trap probes, approximately 60,800 outcome questions and 222,395
chunk-level gold-fact references, filtered down from about 478,000
generated probes and 72,000 generated cross-chunk questions by four
structural passes and a discriminability test.

**And there is no human in any of it.** The word "human" occurs three
times in the paper and all three are in future work or limitations
[E110]. Section 5.7 ends: "Future work includes a random human audit
with error categories and inter-annotator agreement." The annotator is
a model, which the paper states without stating it, in a sentence
comparing annotation designs by cost: "full-history annotation used 33
times more input tokens" [E110]. Input tokens are not a unit in which
human annotation is measured. The limitations section names the
exposure itself: "Rubric rewards reduce sparsity but require
human-agreement and judge-sensitivity checks" [E110].

**So the attribution is real and the ground is not.** Section 6.3
defines the attributed outcome reward as the judge's score for "the
degree to which the answer recovered gold evidence introduced by chunk
t", averaged over the questions citing that chunk [E111]. That is
provenance resolution, which is this company's own central move,
applied to memory banks and shipped. Section 6.6 states the claim that
makes it work: "the supervised unit is an externally verifiable bank
consequence rather than a subjective reasoning step" [E111]. The word
doing the work there is "externally". A model wrote the probe, a frozen
model answers it, a frozen model judges the answer, and the gold facts
were extracted by a model from the same transcript the writer is being
trained on. Nothing in the loop touched the world. The external
verifier is a closed circuit with three frozen models in it, and the
authors list checking it against people as future work.

**What this does to the record, and this is a correction to yesterday
rather than a new alarm.** The day's brief, finding 11, retired "labs
have no verifier for open-ended work" on FDE-Bench and fell back to a
narrower line: "a reference-based verifier needs an accepted answer per
case and the outcome record needs none" [E114]. That narrower line does
not survive this paper. Hy-Memory's reward artifact has no accepted
answer per case and no reference delivery behind it. Its per-case cost
is a model call. Half a million of them.

**The line that does survive is different from both, and it is better
for the pitch than either.** What made this verifier constructible is
not that the authors found a cheaper reference. It is that in memory
writing, everything the output should contain was already present in
the input. A probe can be written from the transcript because the
transcript is the ground truth, so the domain reduces to a closed-form
question about recall. Open-ended work is the class where that
reduction fails. What makes a draft good is not in the brief, and no
amount of model-written probing over the brief will produce it, because
the thing being judged was never in the input to begin with. So the
defensible sentence is about reducibility and not about verifiers or
references: **a lab will synthesise a verifier wherever the quality in
question is recoverable from the input, and it will pay for revealed
outcomes only where it is not.** That sentence also predicts which
domains Ursa Minor can actually sell into, which neither of the two
earlier versions did.

**Confidence and read depth.** High. Abstract verbatim from the listing
page, section 6 in full from the fetch tool, sections 2.3 and 5.1
through 5.8 in full from the local PDF, and the two instruments agree
where they overlap. The one thing not established is whether the paper
contains anything equivalent to `no_generation_provenance`, meaning a
category for evidence present in a correct answer that no chunk
supplied. Section 6.3 attributes only to chunks that introduced gold
evidence, and nothing read says what happens to an answer that recovers
evidence from no chunk. That is a question about sections 7 through 11,
which were not read, so it is left open with its surface named rather
than answered.

**A correction to the record, by the primary source.** The tenth run
recorded that two secondary pages disagreed about this model's
benchmark comparison, one saying it beats Opus 5 and another
attributing the score to a different Claude model, and cited neither
[E114]. The primary source settles it: 55.49 percent against 54.62
percent for Claude Opus 5, on fixed 20 percent benchmark subsamples
[E109]. The caution the tenth run attached to those pages stands.

**What the repository holds.** The full file tree of

`workbuddy.py`, alongside a generic `exported.py` and `chat_exports.py`
[E115]. The registry that declares them carries verified version

`CLAUDE_CONFIG_DIR` defaulting to `.claude/projects`, Codex via
`CODEX_HOME` defaulting to `.codex/sessions`, "Hermes is a recall
target: v0.21.0 verified our server", "verified on 1.18.29, which
completed an MCP handshake", "Recall verified on openclaw 2026.9.1"
[E116].

**So the inbound half of Ursa Major's portability claim is built, and
it is built further than described.** `CLAUDE.md` §3 opens on a user
who juggles Claude, ChatGPT and Gemini and is tired of re-teaching each

and did not put them in the component README.

**What is still absent, with the surface named and the instrument
stated.** The outbound half. Three paths in the tree carry export in

scripts/export_public_snapshot.py` is repository maintenance,
`memhub/apps/web/src/diagnostics-export.ts` is diagnostics, and the
backup contract was read in full: it restores into the same product
and refuses any source outside the One Memory Home, with the failure
code `backup_restore_source_outside_home` [E117]. So a user can carry
eleven vendors' history into this product and cannot carry it out to a
twelfth. The bound on this claim is that it rests on the file tree plus
three files read, not on every one of 1,829 paths.

**What that leaves Ursa Major, stated plainly because the tenth run's
version was too generous.** Not consolidation, which is shipped. Not
consent, which is shipped. Not cross-vendor ingestion, which is shipped
eleven times over. What is left is the direction of travel: a profile
the user can take out and point at a model the vendor does not sell.
That is one clause of `CLAUDE.md` §3 rather than the paragraph, and the
load-bearing constraint it depends on is constraint 4, which already
says the software is not the moat.
