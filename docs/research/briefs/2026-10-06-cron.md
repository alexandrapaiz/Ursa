## What is rising

Ranked by strength of evidence, not by attention.

### 1. Survival of generated text in finished work is now measured by third parties at scale, and the result is not the one Ursa's story assumes (high confidence, primary source, verbatim)

**[G1] Rahman and Shihab, *Will It Survive? Deciphering the Fate of
AI-Generated Code in Open Source*** (arXiv:2601.16809, 23 Jan 2026).
This is **the nearest external work to the outcome record's core
construct that this seat has found in seven runs** — closer than the
post-edit line, closer than the implicit-feedback line, because it is
not an analogy. It is line-level survival analysis of generated text in
real finished work: "survival analysis of 201 open-source projects,
tracking over 200,000 code units authored by AI agents versus humans."

Its headline, verbatim: "Contrary to the disposable code narrative,
agent-authored code survives significantly longer: at the line level, it
exhibits a 15.8 percentage-point lower modification rate and 16% lower
hazard of modification (HR = 0.842, p < 0.001)."

**Read the bad news first, because it is real.** Ursa's §3.2 story
leans on mutation and deletion as the place the correction signal lives.
[G1] says generated lines are modified *less* than human-written ones,
with small effect sizes (Cramér's V = 0.116). An outcome corpus sold on
correction density should not assume coding work is where correction
density lives, and this seat has been assuming it since task-001.

**The asset is larger, and it is one clause.** [G1] also reports that
**"per-agent variation exceeds the agent-human gap."** The field's own
data says the variance worth modelling is *between models*, not between
model and human — and **no dataset in existence can attribute it per
model at span level**, because repository authorship metadata does not
record which model wrote a line. That is cross-model comparison
(`CLAUDE.md` §4, property 1) argued in a third party's numbers instead
of ours. It is the strongest version of that pitch this seat has
written, and it did not exist before this run.

**And the differentiation narrows again, precisely.** What [G1] has is
an *authorship class* recovered from repository metadata — the
retrospective-mining route whose failure modes #114's [F3]
(arXiv:2601.18345) independently documents. Their "human-authored" class
is `no_generation_provenance` **approximated by git blame**, and their
dataset cannot contain a generation produced and discarded before any
commit existed. **The construct was never the differentiator. The join
is.** Added to `docs/research/minor-training-fit.md` §1c this run, with
all three readings, not just the flattering one.

**[G2] Jiang, Li, Hou, Tan and Zhang, *Predicting Developer Acceptance
of AI-Generated Code Suggestions*** (arXiv:2601.21379, 29 Jan 2026) is
the control case that makes [G1] legible. It predicts "whether a
developer will accept the code suggestion **before it is displayed**,"
from IDE telemetry. It does not examine whether accepted suggestions
survive into committed code. *That reading of its boundary is mine, not
a limitation the authors state.* Together [G1] and [G2] bracket the
field exactly where the methods doc §6 said it would be bracketed:
acceptance is instrumented at the insertion point, survival is
reconstructed afterwards from metadata, and nobody joins the two.

### 2. The record's most-cited supporting citation does not say what the record says it says, and its actual recommendation is the construction Ursa rejects (high confidence, and it corrects #82)

**[G3] Kreutzer, Uyheng and Riezler, *Reliability and Learnability of
Human Bandit Feedback for Sequence-to-Sequence Reinforcement
Learning*** (ACL 2018, P18-1165, arXiv:1805.10627).

#82 put this on the watchlist as item 2, unopened, with the note: "If it
holds on a direct read, it is an eight-year-old citation supporting the
methods doc's opening claim." **It does not hold, and the direct read
took one fetch.**

- #82 reported, at second hand through arXiv:2410.02320, that Kreutzer
  found "pairwise preferences are **less reliable** than other forms of
  human feedback." The abstract says: for cardinal (5-point ratings) and
  ordinal (pairwise preferences) feedback, "their intra- and
  inter-annotator α-agreement is **comparable**."
- The reliability advantage appears only after standardization: "best
  reliability is obtained for **standardized cardinal** feedback, and
  cardinal feedback is also easiest to learn and generalize from."
- So **Kreutzer's own remedy for unreliable pairwise feedback is a
  standardized Likert rating scale** — a stated-preference instrument,
  which `docs/vision.md` §0b names as a contradiction of the third
  principle in as many words: "a stated-preference survey contradicts
  the third."

**This mattered within one day.** The second-hand sentence was not
confined to a brief; #82 shipped it into
`docs/research/minor-training-fit.md` §1c, a document feeding O4 KR4.1's
lab one-pager. Cited as written, it hands a post-training reader an
eight-year-old argument *for* the thing Ursa calls drift. **Corrected on
the file this run**, with the narrower claim the source does carry:
*pairwise feedback shows no reliability advantage even against a cheap
rating scale.* That is weaker than §1 wants and it is the only version
the evidence supports.

**The general form, which is the part worth keeping:** #82's own lesson
was that a novelty claim must be searched in the field's vocabulary.
This run adds the dual. **A supporting citation acquired at second hand
is unverified in the same way a novelty claim is** — and it is more
dangerous, because a missed prior-art paper costs credibility once,
while a misquoted citation is reproduced in every document that inherits
the paragraph.
