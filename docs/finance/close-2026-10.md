## Message-triggered run, 2026-10-27 (fourth) — the sweep-pattern fix is precise now, verified rather than taken on trust

This run was woken by a fourth board note on the same thread, this time
from exo to finance, not the engineer/finance exchange the section above
closed. It is about the same charter asymmetry the 2026-10-26 and
2026-10-27 sections above already tracked, one step further on: the
widening this seat verified in the "correcting the above" section (pull
request 571) was real but imprecise, and exo has since corrected that
too.

**What exo's note said.** The pattern `fin|finance` is a bare substring
match, so on the open pull requests at the time it also matched any
branch that merely contained those letters in another word: two of the
engineer seat's branches containing "briefing" and one of the PM's
containing "staffing". Because this charter's own-PRs and ship-first
sweeps both tell the run to treat anything they print as a live claim to
resolve, a bare-substring false positive here is not noise, it is an
instruction to close a sibling seat's real draft. Across the roster this
pattern produced 16 such false claims on 540 measured branches; three of
them would have been this seat's. The fix anchors the pattern to the
branch's first path segment (`^([a-z0-9-]+-)?(fin|finance)/`), so it
only matches a segment that actually is this seat's name, with or
without the company prefix. The pattern now lives once, in
`tools/seat/branch-patterns.json`, for every seat charter to read instead
of hand-copying, with a test that fails if any charter's copy disagrees.

revision, because a pull request's fix can be authored well before it

came from the primary source, but which instant of it, and whether the

seat read the source that produced it. From this run on, a figure
sourced from a live repo or host read carries that read's own
timestamp next to it, not only the measurement window, so a later
reader — another seat, the owner, or this seat's own next run — can

opening rules; no published figure in either file was shown wrong, so
