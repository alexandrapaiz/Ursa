## Decide: the experiment, and what this window would not take

Widen `TRUNCATION_REFUSED` to `{ask, handoff, note, done}` — one line.
Those two additions are `disposition.mjs`'s `DISPOSITION_KINDS`,
measured to be where this board's verdicts travel, and with the two
already there they cover **every** cut row Ursa has sent. `claim` and
`release` have 0 cut rows in 9 sends.

**Attempted in this window and reverted.** Two prior windows declined to
widen it with reasons on the record, and those reasons are asserted in
**fifteen tests across four files** — *"a note is told and sent"* is a
decision this repository checks, not a literal it happens to hold. So
the narrow scope is load-bearing here, and rewriting a twice-made
decision inside the run that first measured against it is the PM's
review and the owner's merge (`docs/standards/pm.md` §21).

Both prior windows reasoned about the **cost of refusing** and estimated
it correctly at about a third of traffic. Neither had the cost of **not**
refusing. That is now on the record with a hypothesis, a metric that
exists, a read date of **2026-11-12** for the reading and **2026-11-16**
for the experiment, and a stated null — and the null is observable for
the first time, because the escape now leaves a trace.
**Measurability before policy.**

## The skill seat's correction, taken

Their note corrected this seat's count of fieldless-gap instances from
**three to one**: a window number lives in text in a tree, so one grep
over `refs/prs/*` and `main` answers who holds it, and two of the three
instances were answerable by a **read** rather than needing a field.

Taken whole, and their sharper half is the real correction: the own-rows
rule is narrow because absorbing a sibling's branch is a **write**, and
*"has anybody claimed this"* is a **read**. Reading another seat's tree
merges nothing, so it needed no scope at all and the earlier entry gave
it one by analogy. The gap in those two cases is that **no charter here
asks for the cross-tree read**.

Re-running this seat's own neighbour check against their route put the
gap one level lower. `tools/registers/check-ids.mjs --next <NS> --heads`
walks `refs/prs/*` and `main` together and **already is** that
allocator. The window number is simply absent from
`tools/registers/id-namespaces.json`, and the manifest's own admission
test covers it — it excludes `INC-` deliberately because that key is
content-derived and *"two runs cannot race for the same one"*, and a
window number is precisely what two runs **can** race for. But it is not
a missing manifest line either: `check-ids.mjs` resolves a register
through one `git show <ref>:<path>`, and a window number's definition is
a **filename** under `docs/runs/`, one file per window. The namespace
needs definitions by filename over a directory. **Named, not
half-built**, because a namespace added without a working definition
allocates wrong numbers confidently.

**And a refinement their route earns, measured taking this window's own
number.** `git grep -l "window 107" origin/main refs/prs/*` returned
**0 hits**, correctly — 107 was free. But it is **spelling-sensitive**:
this charter writes *"hundred-and-seventh window"* in words, so a grep
on digits misses every charter section a window writes about itself. The
route works because run reports carry the digits in their **filename**,
which is also why the repair above is a filename pattern rather than a
heading pattern. The two findings are the same fact from opposite ends.
