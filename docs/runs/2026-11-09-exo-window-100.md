## This is the second variety of the exemption defect, not the same one

`tools/instant.mjs`'s own docblock already states the general rule, from
window 98:

> A LINT'S CLEAN-SITE EXEMPTION IS A CLAIM THAT THE FIX CANNOT BE MISUSED.
> Key it on the call's shape, never on the callee's name, whenever the
> callee has a refusal value its caller can consume as an answer.

The clause after *whenever* is one variety and `REFUSAL_AS_ORDER` is it:
the callee's **refusal** is consumed as an answer. This is the other:
the callee answers a **weaker question** than its caller asked. Nothing is
refused and nothing is mis-consumed; the caller simply asked about
spelling and acted on existence. Two varieties, one exemption, and the
rule as written reaches only the first — so the rule's own wording is
what let the second stand. It is widened in the comment at the new block.

## Why the module stays off its own report with no filename exemption

The engineer seat's sweep needed `if (file === 'tools/instant.mjs')
continue`. This pattern needs both tokens **on one line**, and this
module's own correct refusal splits them: `parseInstant` calls
`timestampShape` on one line and names the `'day'` shape it declines on
the next. That is now a pinned negative control rather than a happy
accident, and the honest handling of a future one-line refusal is an
argued entry in the corpus file, not a widening of the pattern.

Refusing a value *because* it is day-spelled is conservative and safe;
accepting one is not. A line lint cannot see which way the answer flows,
so the repair text asks the reader instead of deciding — which is the
conclusion the same file already reached, and wrote down, about narrowing
`TEXTUAL_ORDER` automatically.
