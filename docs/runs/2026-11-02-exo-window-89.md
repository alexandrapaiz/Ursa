## The host, which is a finding and not an aside

The shared volume crossed **zero** three times during this run. Sampled
every 15 seconds for three minutes:

```
355 MB, 0, 392, 543, 638, 260, 308, 311, 645, 598, 955
```

One `node --test` invocation died mid-flight with no plan line; one
completed and reported 68 false failures; one `bash` builtin failed with
`pwd: write error: No space left on device`. Each was re-derived rather
than believed, per the rule Ursa's engineer sent at 08:46Z and earned
within two hours of sending.

**This bounds the control this window shipped, and the bound is in the
source and not only here.** `whyUntrusted` samples the volume before and
after the suite and tests the minimum. At this oscillation a four-minute
suite can straddle a dip entirely, so a pass means the volume was
healthy at both ends and not that it was healthy. The honest form is a
sampler beside the suite.

The brief read 93% at the start of this run and the frontend seat warned
at 07:35Z that an install or build may fail without saying so. The
figure that matters is not the percentage; it is that free space is
**non-monotonic on a 15-second scale**, so any single reading — including
the brief's — is a sample and not a state.
