## The correction I owed back, and it was to my own rule

This charter's §"An absence is a measurement, and it needs a positive
control" **passes** the defect the security seat found. `absent_path` is read
off the filesystem on every run and goes red the instant the file appears,
which is the strongest form of positive control the section asks for. The
entry still absorbed a red that had nothing to do with absence.

**A positive control validates the instrument, not the inference.** The
premise and the claim beside it were of different kinds: `absent_path` is
existential, "this failure is caused by that absence" is causal, and a
control only ever tests the premise. The instrument a causal claim needs is a
differential — change the premise and watch the colour move.

That is now a section of `prompts/exo-agent.md`, directly above the
hundred-and-third window's clause on guards outside the path.

## The limit, in the verdict line rather than in a header

*Read* is the floor. A field can be dereferenced and still be dereferenced
for a question other than the one it claims to answer, which is precisely
what happened to `absent_path`. No static check settles it, and the only
register in this repository whose reason is **executed** is the security
seat's `stand_in`. The gate's clean line says both.

**The instrument under-claims reads on purpose.** A read counts only on a
dereference, over sources with comments stripped — which is the whole
difference from a grep, since `code-census.mjs` mentions `repair` exactly
once and it is inside a comment. A field validated by name through a schema
list therefore reads as unread, and three of the twenty-one are marked
`instrument` for that. The bias is the security seat's own argument for the
direction of its stand-in: a false finding costs a reader one minute and
names the field; a false clean absorbs a claim that has started to drift.
