Three known advisories, each with a named repair and that repair marked
breaking, reported on no line of the gate. Two independent omissions produced
it, and only one of them is the one security named.

1. **The remediation hint reached one kind of three.** `fixAvailable` was read
   inside the object literal pushed onto `violations` and nowhere else. The
   other three paths an advisory can take — a below-floor warning, a warning
   allowed by a live exception, an elapsed exception — each built a record
   with no `fix` field. Those are the paths this repository's own advisories
   take, so the hint was reachable from the one case the gate was tested on.
2. **The severity filter dropped `low` and `info` entirely.** The report
   filter was `if (sev === 'high' || sev === 'moderate')`, so anything below
   moderate fell through a bare `continue` and was recorded nowhere. Beside
   it, the per-package count line printed `critical`, `high` and `moderate`
   out of an object carrying five severities and a total, so the one severity
   that was nonzero was the one not printed.

The second is why the output above reads as a clean package. A reader is not
told "three low advisories, below the floor, not blocking". A reader is told
zero.

## What shipped

`scripts/dep-floor-classify.mjs`, a new pure module, plus
`scripts/dep-floor-classify.test.mjs`, 12 cases. `scripts/dep-floor.mjs`
now imports it.

The split is not invention. `scripts/dep-floor-summary.mjs` already exists for
exactly this reason and says so in its own header: `dep-floor.mjs` does its
work at import time, walking the repository and shelling out to `npm audit`
twice per package before exiting, so there is no way to import it and ask it a
question. Every branch that classified an advisory was unreachable from a
test, which is how two of them stayed wrong for two months. This is that same
split applied to the part that was still inside the script.

Three exports:

- `fixHint(fixAvailable)` — npm's own answer to what would repair this, as one
  phrase, called once per record so it cannot be present on one kind and
  absent on the others. Renders `npm audit fix`, `vite@5.4.21`,
  `shadcn@1.0.0 (semver-major)`, or `none published`.
- `classifyAdvisory({severity, inProd, exceptionExpires, nowMs})` — which of
  `violation`, `expired`, `warning` one advisory is, plus its scope and the
  reason. **Total by construction**: every input returns a kind, so nothing
  can be dropped by falling off the end of a filter. Asserted over the whole
  severity-by-scope-by-exception cross product, which is the property the old
  filter did not have.
- `severityCounts(totals)` — the count line, built by mapping over
  `SEVERITIES` rather than a written-out list. Its test asserts that the
  rendered line names every key of a real `metadata.vulnerabilities` object,
  so a severity npm adds later makes the test fail instead of making the line
  quietly incomplete.

## What deliberately did not change

- **The floor.** `critical` anywhere and `high` in a production tree are what
  fail, unchanged. `failed` is still `violations.length > 0 || expired.length
  > 0`, so the exit status is computed from the verdict and not from the last
  thing that ran, which is the clause Ursa/exo asked this seat to carry
  forward after three seats hit the opposite shape in one night.
- **`summaryLine()`.** Untouched. The 2026-11-01 ledger entry proposes
  splitting it on breaking-versus-in-range, and that entry's status is
  `proposed`, which only the owner moves. Correcting an entry is not
  permission to build it. What shipped is existing behaviour made honest,
  which is a break-fix.
- **`dep-floor.allow.json`.** Not read differently. `findException` is now
  called for every advisory rather than only the failing ones, and
  `classifyAdvisory` returns `why: 'below-floor'` when an exception matches
  something that was never above the floor, so such an advisory keeps the true
  reason on its warn line instead of borrowing the exception's. Pinned by a
  test. The expiry comparison stays `>=`, also pinned, so a refactor cannot
  quietly make expiry exclusive.
