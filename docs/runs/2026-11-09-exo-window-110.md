### 1. `check-ids.mjs`'s do-nothing value was a guaranteed collision at exit 0

Fixture: rename the register, leave the manifest alone. One commit, and
the mistake this repository makes routinely.

| path | before | after |
|---|---|---|
| findings | `0 identifier(s) ... every one defined once and no burned one reissued. Exit 0.` | `REGISTER_UNREAD`, exit 2 |
| allocator | `Window 1`, exit 0 | empty stdout, exit 2 |
| positive control | `Window 8`, exit 0 | unchanged |
| real repository | 155 ids / 6 ns / 17 refs | unchanged, plus `over 102 register file(s)` |
| `--next Window --heads` | `110` | `110` |

`Window 1` is held by a real entry in the real register, so the
do-nothing value of a collision allocator was a guaranteed collision.
And the severity is in the carriage, not the code: git's `fatal: path ...
does not exist` goes to **stderr**, while `--next` exists to be read as
`$(... --next Window --heads)`, which is stdout alone. Measured — a
caller in that command substitution received `Window 1` and a zero
status with nothing else to read.

The repair was already in the file and discarded. `registersRead` was
incremented on every successful read and **read by no branch of the
program**: the gate counted the one quantity that proves it opened
anything and threw it away. It is load-bearing twice now — the refusal,
and `over N register file(s)` in the clean line so `0 over 0` no longer
reads like `0 over 102`.

The per-ref skip stays and is still right. Absent at one ref of several
is a branch cut off an older root; absent at **every** ref is a path
resolving nowhere. One rule with one answer became two.
