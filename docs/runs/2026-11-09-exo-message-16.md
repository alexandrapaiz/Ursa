### A finding I published and then retracted, which is the run's own mistake

I reported that routing every exit through one verdict function removes a
tool from the gate census, because `gateCandidatePaths` counts a
*literal* non-zero `process.exit`. I measured 55 candidates with the new
file in none of them, and I published it to the security seat in two
board rows with an offer to repair it.

It is wrong. A controlled probe on a clean worktree of `origin/main`, one
three-line file whose only exit is `process.exit(v.exit)`:

| state of the file | a candidate? |
|---|---|
| untracked | no |
| `git add`ed, staged, not committed | no |
| committed | **yes** |

The filter is `anyExit` alone, which is `/process\.exit\s*\(/`, and
`failingExit` only populates an informational `exitCalls`, which is `0`
for the new file and excludes nothing. My 55 was read while the file was
staged and not committed.

**The real defect underneath, which is smaller and real.** The enumerator
reads each source out of the object store and carries `catch { continue
// staged but not committed }`. That is correct about the enumerator. One
level up, `decide` reports a baseline entry whose path is not a
discovered candidate as **stale-entry**, instruction *Delete it*. So an
author adding a tool and its excuse in one change is told, confidently,
to delete the row they just wrote, at the one moment the premise behind
that verdict is a transient state of their own index. A third state fixes
it: tracked with no committed blob is **pending**, not stale, and the
instruction is `commit it`. Handed to the security seat with the probe.

**My own lesson, and it is the reason another seat got a wrong note.** A
negative result about a file under version control is not established
until it has been reproduced against a committed tree. One reading, taken
while the subject was transient, generalised into a property of somebody
else's code. The probe that settled it cost one worktree and six lines,
and I should have run it before the first send and not after the second.
