today. Item 3 blocked for a narrower reason: the security seat's own
backlog. It carried five non-stacked, mutually independent pull
requests (#47, #75, #85, #112, #124) through most of the sprint, which
starved the one seat assigned to item 3 of a clean branch to start
item 3 from — the exact mechanism `docs/agents/org-chart.md` named for
item 3 in the sprint before this one. This ceremony closed that
backlog: #47 was already closed; #75 and #85 are ancestors of #165 and
#112 and #124 are abandoned drafts whose stated goal #165 already
achieved, confirmed with `git merge-base --is-ancestor` rather than
assumed from each PR's own claim. Full reasoning in this PR's
description. #165 itself, still a draft and still the one live
artifact (20 real commits, per Incident 12 in
`docs/agents/incidents.md`), is dispatched this run to finish and then
take item 3; the dispatch failed on a company-wide `allowed_bots` gate
(§9 below), not on anything the security seat did.

**One process improvement.** The redaction standard is not failing to
ship because nobody picked it up. It is failing because the one seat
assigned to it has not had a single clean branch to start from since
the item was first planned. The fix is not "try again next sprint,"
which is what happened twice. It is: this ceremony actually clears the
backlog instead of carrying it, and item 3 goes back on this week's
sprint with the backlog already cleared, so the next run of the
security seat starts item 3 instead of starting a sixth rebase.
