sprint week, on green CI, with no stuck branch. What blocked was the

on `main` for 28 days while the underlying engineering did not stall:
77 engineer-branch PRs alone merged in that window (per the OKR
2026-11-01 check-in), including the three items above. Twenty-five
message-triggered PM passes on 2026-11-09 alone each correctly read
`pm.md` §11.1 ("Monday, or a dispatch that says so") as naming the
ceremony-cron slot rather than the calendar day, and none of them was
wrong to say so on its own — the finding recorded in `docs/decisions.md`
("the Monday ceremony has not run in four weeks," pass twenty-five) is
that twenty-five correct, narrow passes compound into one structural
gap. This run is the host's `ursa-pm` cron slot actually firing on a
Monday (trigger: `cron`, not a message dispatch), and it is doing
exactly what pass twenty-five proposed as the fallback: running the
ceremony because the newest sprint file predates today. Whether that
is this run closing the gap on its own cron merits, or the 48-hour
silence-rule proposal from pass twenty-five quietly taking effect, is
not resolvable from inside this run; either way the practical gap
closes today.

**Process improvement.** Two, both already partly in motion, named
here rather than re-discovered:

1. `docs/sprints/pending.md` has grown to over 5,200 lines across
   thirty-plus "Top three for the owner" sections, almost entirely
   from the six-hour and message passes that ran correctly but without
   a ceremony to close against. That is itself a cost: a file this
   long is expensive for every run to read before acting, which is the
   opposite of what a pending tracker is for. This run archives
   everything older than today's ceremony into
   `docs/sprints/pending-archive-2026-11-09.md` and leaves a pointer,
   so the live file tracks the current sprint's own window going
   forward. Full accounting in this PR's description.
2. The thing actually missing this sprint was never engineering
   capacity. It was a ceremony run that identified itself as one. The
   concrete fix is the one pass twenty-five already proposed to the
   ledger and is still inside its 48-hour window: a message-triggered
   Monday run that finds no sprint file opened that week should treat
   that as `pm.md` §11.1's "a dispatch that says so" and run the
   ceremony before anything else. This retro does not re-decide that;
   it records that today's cron-triggered run reached the same
   destination by its own scheduled path, which is independent
   evidence for adopting the proposal as a safety net rather than
   evidence that the net is unneeded — a cron slot that fires reliably
   today is not a guarantee it fires reliably next Monday.
