## The exact in-band case, measure-focus on the home page at desktop

Both runs printed the byte-identical headline and both exited 0.

                               live        never-ran
  focusable in the DOM, home     6             5
  tab stops Tab found, home      6             6
  stops with an area reading    28            27
  headline                  0 of 28 tab stops below a floor   (identical)
  exit                           0             0

The stop that changed is `CopyLine`'s scroll region, and what changed is
its accessible name:

  live        pre "command, scrolls sideways"   493x44      ok
  never-ran   pre "mkdir -p .github/workflows curl -fsSL ht" 492.84x43.75  UNDECLARED

So the dead page produced a NEW verdict class, `UNDECLARED`, the tally
went from `27 ok, 1 COMPOSITE` to `26 ok, 1 UNDECLARED, 1 COMPOSITE`, and
the headline did not move. That is exo's third line: the in-band value
that is also the right answer today. Nothing is below a floor on either
page, so the number is true and carries no information.

Two of the kit's verdict classes, `UNDECLARED` and `GONE_FROM_DOM`, were
counted in that tally and reached neither the headline nor the status.
Repaired here and now named in both.

## The same rule one layer out, and it cost a false red while this run worked

Four of the kit's selftests bind a fixed port for their fixture server and
route a bind failure to exit 1, which is the status those files use for
`the instrument under test answered wrongly`.

  port 4975 was held by another seat's python3, pid 1416700, on this host
  selftest/check-narrow.mjs   Error: fixture never answered   exit 1

Verified on the pristine pre-run kit: byte-identical failure, so it is the
host and not this run's edits. Ports are shared between the eleven seats
the way `/tmp` is, which is `runner-facts.md`'s fact with a different
resource in it. After `lib/fixture-server.mjs`:

  check-narrow      exit 1  ->  exit 0, all 7 expectations hold
  check-contrast    exit 0  ->  exit 0, all 23 hold
  check-hit-areas   exit 0  ->  exit 0
  check-reached     exit 0  ->  exit 0

One measurement inside that repair worth keeping: on this host a `fetch`
to a port nothing listens on returns `TimeoutError: The operation was
aborted due to timeout` with `err.cause` undefined, so a refusal is not
distinguishable from a slow service by reading the error. A raw socket
returns `ECONNREFUSED`. The first version of the free-port finder read the
fetch error, called every empty port occupied, and refused twenty times in
a row, which is the over-refusal trap three files over.
