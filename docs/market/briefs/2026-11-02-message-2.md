## What this run found

1. **"Outcome-based pricing" already has a meaning in this market, and
   it isn't Minor's.** A data-licensing market report (pebblous.ai)
   names "outcome-linked pricing" — paying a seller by a measured
   downstream result, its example being Reddit pushing Google to pay
   per citation an AI answer gives Reddit's content — as the newest of
   four generations of AI data-licensing billing. That's bulk-content
   licensing, a different market from Minor's RLHF/preference data,
   but the word collision reaches Minor directly: CLAUDE.md §1 calls
   Minor's product an "outcome record," and §4 prices it as a flat
   annual license, never a result-contingent fee. So what: a lab
   procurement contact who has read any generic "AI data licensing
   trends" piece could reasonably expect Minor's pitch to be a
   pay-per-result structure it isn't. A one-line disambiguation the
   first time KR4.1's brief says "outcome" costs nothing and closes
   the gap. Ledger proposal below.
2. **A well-trafficked practitioner critique of memory plugins
   independently names the exact defect Major's own non-negotiable
   already answers.** A Hacker News post with real traction for this
   category (392 points, 312 comments; posted 2026-10-03, found this
   run rather than in its own week) argues coding-agent memory plugins
   are the wrong fix, and names "unauditable" storage — memories
   accumulate in a way that makes it "impossible to track which
   memories influence behavior" — as the first failure. The post isn't
   about cross-model portability and its own proposed fix
   (maintained documentation) isn't a Major competitor. But the
   defect it names is precisely CLAUDE.md's non-negotiable #2 (a user
   can always see what's been inferred), and this file already has a
   concrete case of a shipped competitor failing that test (OpenAI's
   Memory Summary edits not reliably reaching the memory the model
   actually uses, docs/market/landscape.md, 2026-10-05). So what: this
   is independent, non-Minor-sourced, well-read corroboration that
   auditability is a live practitioner complaint, not a differentiator
   Major invented to sound good. No ledger proposal needed; it
   strengthens an existing claim.
3. **Everything else checked this run was already on file.** The
   Surge/Mercor-to-China dual-sale story, Mercor's $614M H1/$2B
   annualized revenue and $20B valuation talks, and MemoryLake's
   "neutral memory store" positioning all turned up again in general

   source. Recorded here only so the next run doesn't re-spend a

## Report for the owner

This week's clearest fact isn't a new competitor or a new price, it's
a word problem sitting on top of an unchanged gap: the wider AI
data-licensing market has started using "outcome-based pricing" to
mean paying by a downstream result (Reddit's per-citation push with
Google), while Minor's own "outcome record" means something structural
and unrelated (a generation joined backward to what survived) priced
as a flat annual license. If KR4.1's lab brief uses the word "outcome"
without a line distinguishing the two, a procurement reader primed by
the market's own usage could misread the pitch. Cheap to fix, now on
the ledger. Separately, a well-read Hacker News critique of memory
plugins (392 points) independently named "unauditable" storage as the
defect practitioners actually complain about, which is corroboration
for Major's own inspectability promise from a source with no stake in
Ursa at all. Nothing this run argues for a pricing or positioning
change the owner needs to make today; both findings are additions to
language already in flight, not new open questions. The standing open
decision from prior runs — whether Minor commits publicly to a
no-dual-sale, single-buyer-tier data-provenance guarantee before
KR4.1's brief is drafted — is still open and still the owner's call,
not this seat's.
