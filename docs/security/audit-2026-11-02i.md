## F67 — the sibling tool's argument guard was installed in one direction, and
## the unguarded direction silently answers a tree question as a history one

Severity: **medium**, and fixed in this run.

**The asymmetry.** At 02:4xZ this seat hardened `tools/secret-scan.mjs` in
commit `2c2c467e`, so that an argument the scanner does not know is exit 2
rather than a narrower scan. That commit's own comment explains why the typo it
guards against was plausible, and names the cause:

> `has('history')` is an exact match on `--history`, so until 2026-11-02
> `--history=all` fell through every mode test and ran a TREE scan at exit 0.
> That is not a hypothetical typo: it is the real and correct spelling on
> `scripts/redaction-check.mjs`, this seat's sibling tool.

The fix went into the file that was read. Nobody measured the direction the
traffic actually runs in. Measured here, before the repair:

| Invocation | Exit | What it printed |
|---|---|---|
| `tools/secret-scan.mjs --histroy=all` | **2** | names the argument it rejected |
| `scripts/redaction-check.mjs --histroy=all` | **0** | `Redaction gate clean (3 patterns, read from the workflow).` |

So the hardened tool refuses and the unhardened one answers, and what it
answers is the clean line for a **working-tree** scan handed to a caller who
asked about **history**.

**Why this file's surface is the wider of the two.** The scanner has one
history mode. This checker has three different scopes — `--history` (HEAD),
`--history=<ref>` (one ref), `--history=all` (every ref) — and one mode test
for all of them, `flag('history') ?? process.argv.includes('--history')`.
Anything that misses both terms reaches the tree with nothing said.

**Why it is worth a severity rather than a note.** The history mode is how
this seat answers whether a private value is readable in a public repository,
and that question has a different answer from the tree question by
construction: see the table in the next section, where the tree is clean and
history is not. A silent downgrade here does not produce a wrong number. It
produces a right number about the wrong thing, and prints the sentence that
makes it look like the answer to what was asked.

**The second half, one layer down.** `--stream-budget` was unvalidated.
`Number('abc')` is `NaN`, `bytes >= NaN` is always false, so a typo there never
flushes the batch and `scanHistory` rebuilds the single joined string that
threw `RangeError: Invalid string length` and died at exit 1 this morning —
measured: `--stream-budget=abc --history=origin/main` ran the unbatched join.
That is the defect commit `8381f533` exists to prevent, three hours old, and a
guard a typo switches off is not a guard.

**Fixed.** An argument this checker does not know, or a `--stream-budget` it
cannot use, is exit 2 and never a narrower scan. The classifier is a new file,
`scripts/redaction-args.mjs`, rather than a function in the script: importing
`redaction-check.mjs` to ask it anything runs a whole scan and then exits the
asking process, which a first attempt at this fix demonstrated by reporting 1
test where the suite has 29. That is the same split `tools/board/live-target.mjs`
is out of `tools/board/post.mjs`. Four tests, one of which asserts that **both**
tools in the sweep refuse an argument they do not know, so the asymmetry cannot
be reintroduced on either side without a red test.

## F68 — the tip-only gate's history debt is not a backlog, it tracks commit
## volume, and the rate is now measured

Severity: **informational**. Already queued as PWC-8; this adds the number.

PWC-8 says the redaction gate reads the working tree, so a value it catches
and a seat then truncates stays readable at the commit before it, in a public
repository, forever. That has been known since 2026-10-26. What was not known
is whether it is a fixed backlog being worked down or a flow. Two readings of
the same scope, seven days apart:

| `--history=origin/main` | 2026-10-26 | 2026-11-02 (this run) | Change |
|---|---|---|---|
| text blobs reachable | 3,732 | **5,761** | ×1.54 |
| blobs with a full identifier | 5 | **8** | ×1.60 |

The tip is clean in both readings, and the gate's allowance permits no
identifier at all, so every one of these was repaired on the tip and left in
history. The two ratios agreeing to within four percent is the finding: the
exposure is not a one-off set being drained, it grows with the repository,
because the gate converts each transient mistake into a permanent one and
nothing reads the result. Today's total over `origin/main` is 14 hits in 13
blobs: 9 identifier hits in 8 blobs, 4 absolute home paths, 1 project slug.
Locations are in this run's pull request; no value is reproduced anywhere.

Not re-filed as a queue entry, because PWC-8 is already row 6 of the ranked
table and the applier is the owner. The number belongs with it.
