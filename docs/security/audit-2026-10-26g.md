## 4. The finding this run owns

### F32. The redaction gate has never looked at an image, and this repository has 1,175 of them (queued as PWC-13)

The gate's scan is `grep -rInE`. The `-I` flag means "process a binary
file as if it did not contain matching data". So the three patterns that
exist to catch Class B home paths, Claude project slugs and Class C
session identifiers have only ever been applied to text files.

**Verified, not inferred.** A one pixel PNG was built carrying a
fabricated home path and a fabricated full UUID in an uncompressed
`tEXt` chunk, beside a plain text file carrying the same two strings.
Under GNU grep 3.11, which is what `ubuntu-latest` runs, the gate's own
flags report the text file and say nothing at all about the image. The
same command without `-I` reports `binary file matches` on it. One flag
is the whole of the behaviour. The probe was deleted after measuring.

One methodology note, because this run's first measurement was wrong and
silently so. GNU grep suppresses the `binary file matches` message when
its stdout is `/dev/null`, so a count taken with `2>&1 >/dev/null`
reports zero binary matches whatever the tree holds. The first pass here
did exactly that and would have published a clean number produced by the
measurement rather than by the tree. Both streams go to files instead,
and the method was proved against the probe before being pointed at the
repository. Also worth knowing for anyone reading a transcript: `grep`
on this sandbox's PATH is ugrep 7.8.4 and not GNU grep, and the two
differ here, so the figures above were taken from `/bin/grep`.

**The surface.** 1,175 tracked image files, 1,170 of them PNG, nearly
all screenshots under `docs/design/reviews/` from the design review
practice. It grows daily. The one pull request that merged since the
last audit added twenty.

**Nothing is disclosed today, checked both ways.** All 1,170 PNGs were
parsed at the chunk level and **not one carries a `tEXt`, `iTXt` or
`zTXt` chunk**, so the metadata channel holds nothing. The rendered
content was sampled, which is the half no scanner can read: the
dashboard captures show a store named `store-demo` with truncated eight
character identifiers and no prompt text, and the record viewer captures
show the published explainer page and the `mini-fixture` record. Both
are fixtures. No Class A verbatim text from a real session appeared in
anything sampled.

**What the fix costs, measured.** All three patterns were run over the
whole tree without `-I`, with the gate's exclusions. Binary files
matched **zero** times on all three, and the 29 text hits were all
covered by the allowance the gate already applies. So the worry that
high entropy image data would trip the UUID pattern by chance is not
true at this repository's size, and dropping `-I` costs nothing today.

**Why this run did not fix it.** The change is one flag in
`.github/workflows/redaction-gate.yml`. Workflow files belong to HQ
under `docs/standards/pm.md` §15, and this seat's charter forbids
touching workflows outright. Nothing on that path was attempted. It is
queued as **PWC-13** with the exact change, including the detail that
the message goes to stderr so the `hits` capture needs `2>&1` or the
applied fix catches nothing, and handed to HQ on the board.

**The half that no flag fixes, which is the reason to write this up.**
Removing `-I` finds a string sitting in an image's metadata. It cannot
read a screenshot. The record viewer embeds prompt text by the redaction
standard's own §2, so a capture of a real record rather than a fixture
would put Class A verbatim human text into a public repository where no
gate of any kind can see it, and Class A is the class that caused
incident 2. What prevents that today is that the capture harness points
at a demo store, which is a convention and not a control. That is the
same shape as run 11's scratch directory finding, and it is the second
time in two runs that the thing standing between this company and a
disclosure is a run remembering something.

So the standard was amended in the same pull request rather than left to
the queue. `docs/security/redaction-standard.md` §2 now lists rendered
images as surface 5, and §7 states the rule for it plainly, which is
capture fixtures and never a real project's records.
