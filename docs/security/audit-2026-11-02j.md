## F70 — the prescribed repair reaches binary files and reports every grep diagnostic as a leak

Severity: **medium**, latent. It cannot fire until the gate changes, and it
would fire on the day it does.

This is new, and it is a defect in PWC-13's remedy rather than in its
diagnosis. The diagnosis holds: `-I` makes every binary file an unscanned
surface, and this repository tracks 1,318 images.

**What was measured.** The gate's own `scan()` body was run against a fixture
holding a fabricated Class B home path, under GNU grep 3.11, which is what
`ubuntu-latest` runs. No value from this repository was used and none is
reproduced here.

| Pipeline | Binary carrier | Plain text carrier |
|---|---|---|
| `-rInE` with `2>/dev/null` (ships today) | clean | red |
| `-rnE` with `2>/dev/null` (the flag alone) | **clean** | red |
| `-rnE` with `2>&1` (what the entry prescribes) | red | red |
| `-rnaE` with `2>/dev/null`, allowance unchanged | **clean** | red |
| `-rnaE` with `2>/dev/null`, allowance given `-a` | red | red |
| `-rlaE` with `2>/dev/null` | red | red |

Two rows are worth reading twice. The flag alone does nothing, because GNU
grep announces a binary match only on standard error and the gate discards
that stream: stdout 0 bytes, stderr 51 bytes, grep exit 0, gate verdict
clean. And forcing the bytes onto stdout with `-a` also does nothing on its
own, because the allowance is itself a grep with no `-a`, so it treats the
piped bytes the same way and emits nothing one stage later.

**The new defect.** The prescribed `2>&1` does reach a binary carrier. It
also merges everything else grep writes to that stream into `hits`, and
`[ -n "$hits" ]` is the whole of the gate's test. Measured on a tree carrying
no private value at all: a directory the runner cannot read turns the gate red
under the label

> Absolute home path with a real username. Write /Users/<you>/ or ~/ instead.

The label names a cause that is false and prescribes a repair that does
nothing, which is the defect class `tools/gates/verdict-shape.mjs` exists for.

**And the gate has no good state between its two.** As it ships,
`2>/dev/null` discards that condition, so a scan that could not read part of
the tree is reported clean. With `2>&1`, the same condition is reported as a
leak. Neither is "the scan did not finish", which is a ground fault and needs
its own exit code.

**Why the obvious repair is worse than both.** The gate prints `head -20` of
its hits into the Actions log of a public repository. On a binary carrier
`-a` prints raw file bytes there, so the fix that merely forces the match
through would turn the redaction gate into a disclosure channel for the
values it exists to catch. `-l` names the file and quotes none of it, which
is this charter's rule stated outright and the discipline
`tools/image-metadata.mjs` already keeps by reading chunk types and never
chunk contents.

**What PWC-13 now asks for**, three properties with a reason each rather than
one flag: reach, do not echo the bytes, and classify standard error instead
of merging it. Two consequences of the second are named in the entry rather
than left to be discovered: the line-scoped allowance has no line to match on
once the scan carries paths, and `-l` with `-a` still reports by path, which
is the location-only shape PWC-8 (3) asks for, so the two entries agree.

**The gate itself is untouched.** `.github/workflows/` belongs to HQ under
docs/standards/pm.md §15 and this charter forbids the path outright. Nothing
was attempted on it. What changed is the queue entry and the instrument.

### The instrument, so this is checkable rather than arguable

`scripts/gate-binary-reach.mjs` reads the gate's pipeline out of the workflow
and names the first of five things in the way. It has no `process.exit`: it is
the predicate a gate or a test asks, not a gate.

`scripts/gate-binary-reach.test.mjs` is the half that matters. It builds a
fixture carrying fabricated values, runs each candidate pipeline with the real
grep, and checks the prediction against what actually happens, so a grep that
changes its binary reporting turns the suite red instead of turning the queue
entry quietly wrong. It also asserts that every candidate still catches a
plain text carrier, so a repair that reaches binary files by breaking the text
case is visible rather than scored as progress. Thirteen cases, all passing.

One constraint, named because it explains a choice an earlier run made. The
fixture value has to match the gate's own pattern or none of this measures
anything, which means a literal spelling of it in the test file turns the gate
red on that file. It is assembled at runtime from parts that carry no matching
substring. That is why run 12's probe on 2026-10-26 was built and discarded
instead of committed, and it is a real constraint of testing a gate from
inside the tree it scans.

## F71 — a tripwire on another repository's source text called HQ's repair a regression

Severity: **low** as exposure, and worth the words as a method finding.

such filter` appeared inside the events route's own window in HQ's
`api.py` on the host. It went red today.

HQ moved that refusal into a shared helper, `self.refuse_unknown(self.EVENT_FILTERS)`,
on 2026-11-02. The host source says why in its own comment: the route had
restated the refusal in its own words, so two copies of the sentence existed
and HQ's `test_one_implementation` — the assertion that keeps a third from
appearing — was red on their `main` that same day.

**The two assertions were in direct conflict.** Ours could only be satisfied
by a copy local to the route. Theirs forbids a second copy. So ours was
pressure toward the duplication theirs catches, and it reported HQ doing the
right thing as the regression of a fix HQ had made.

**The behaviour was checked before the test was touched**, which is this
file's own prescribed method — decide a parameter is honoured by sending an
impossible value, not by reading a schema. Against the live board:
`GET /api/events?nosuchfilter=1` answers 400 with `no such filter: nosuchfilter`
and a `honours` array, and an impossible `company` returns 0 rows against 5
unfiltered. The route refuses, and it always did. Both probes are GETs.

Either shape now satisfies the property, and the assertion message tells the
next reader to probe the route before believing it, because a rename of the
helper reads identically to a regression.
