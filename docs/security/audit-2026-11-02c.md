## 1. The board item, and what the two halves are

The item says it plainly: the redaction gate "skips every binary file
and we have over a thousand committed screenshots that nothing has ever
looked at". The code change is one flag, `-I` in the gate's `grep`, and
that flag lives in `.github/workflows/`, which belongs to HQ. It was
queued as PWC-13 on 2026-10-26, HQ's centralizer routed it to HQ's
project manager the same evening rather than applying it, and the flag
is still there today. Seven days.

So the item was walled, and a walled item is where a seat has to decide
whether the wall is the whole job. It was not. Dropping `-I` applies the
gate's three patterns to a binary file. There is a narrower question
underneath it that no pattern can ask, and the answer to that one is
machine checkable without the flag: **does a committed image carry a
text channel at all?**

A PNG's text lives in four ancillary chunks, `tEXt`, `zTXt`, `iTXt` and
`eXIf`. A file with none of them is not carrying a string of any shape,
matched or unmatched. So the two changes compose rather than overlap.
This gate closes the channel. Dropping `-I` reads what comes through a
channel somebody opens on purpose, and still reaches two things this
gate does not: a format it has no reader for, and text in a binary file
that is not an image at all. PWC-13 is annotated to say exactly that, so
nobody closes it as done on the strength of this.

## 2. The gate, and the chunk it found

`tools/image-metadata.mjs`, with its verdict as a pure module and its
input space declared, which makes it the seventh extraction under the
ideas entry for that work. The enumerator now drives 47 branches to 36
distinct causes with no finding against any of them.

What it does: walks every tracked image at the container level and fails
when one holds a chunk that can hold text. It never reads a chunk's
contents, only its four character type and its length, so a value it
finds stays unquoted even in the output of the thing that found it. That
is the charter's rule and the structure gives it for free rather than by
discipline.

What it refuses: a format it has no reader for, and a container whose
chunk lengths do not reach the end of the file. Both exit 2, never a
clean zero, because a scan that could not run must not be
indistinguishable from a scan that found nothing. SVG is left alone by
name and not by accident, since it is text and the gate's own three
patterns already read all five committed ones.

**The rule is zero, and it was not zero.** 1,303 tracked images, 8,914
container chunks. One carrier: `ursa-minor/app/favicon.ico`, the Next.js
scaffold favicon, whose fourth directory entry is a 256 pixel PNG
carrying an `eXIf` chunk. Read at the tag level: one IFD entry pointing
at an Exif sub-IFD holding exactly two tags, `PixelXDimension` and
`PixelYDimension`, which duplicate what `IHDR` already declares. No
author, no software string, no path, no location. Benign, and recorded as
**F54** at informational severity rather than passed over, because the
question a gate answers is whether the channel is open and this one was.

Stripped, and the behaviour preservation was measured rather than
asserted: the three bitmap entries are byte-identical, `IHDR` is
identical, the compressed data is identical, and all 262,400 inflated
pixel bytes are identical. The file is 68 bytes smaller and renders the
same.

**Why zero and not an allowance.** The alternative was to permit an
`eXIf` chunk holding only dimension tags, which means reading the chunk's
contents to decide, in the one tool whose whole claim is that it does
not. A gate with an allowance on its first commit is a gate that has
already started negotiating.

## 3. F52 — the all-refs history scan died on a string limit

`scripts/redaction-check.mjs --history=all` is this seat's answer to the
only question that matters about a public repository, which is whether a
private value is readable on **any** ref rather than on one ref's
ancestry. It was added earlier today. On the first complete clone it has
ever had, it crashed.

It joined every text line of every blob in scope into one JavaScript
string and grepped that once per pattern. That is the right shape at one
ref and impossible at every ref. 4,075 commits, 298 remote-tracking
refs, 7,046 blobs: `RangeError: Invalid string length` out of
`Array.join`, unhandled, process dead.

**The part that makes it worse than a crash.** Node exits 1 on an
uncaught throw, and exit 1 on this tool means the tree is dirty. So the
crash was indistinguishable from a finding to anything reading the
status, which is the inverse of the property the tool is built around.

**Why nobody had hit it.** The clone a seat is handed is shallow and
single-branch, and this mode correctly refuses there. So the only clone
shape the mode can run on is the only one it had never been run on. The
refusal that protects the result is also what hid the defect behind it.

The fix is a byte budget, and blob count was never a safe bound: blobs
are capped at 4 MiB, so the old batch of 500 bounded one stream at 2
GiB, four times the limit it hit. The budget is 64 MiB and the largest
readable blob is a sixteenth of it, so every batch fits whatever the
blobs turn out to be.

Two tests, at a one byte budget so every blob is its own batch and every
hit crosses a boundary. They check the thing batching can actually
break, which is a line number read against the wrong batch's frames,
since `grep -n` numbers each stream from 1. The second asserts the
batched and unbatched scans of one repository print the same bytes.

After the fix the mode completes and reports 94 hits across every ref,
which is the standing condition the previous run recorded and not news.
It read zero of them while it was crashing.

## 4. F53 — the secret scanner answered a narrower scan at exit 0

`tools/secret-scan.mjs` tests its mode with `has('history')`, an exact
match on `--history`. So `--history=all` fell through every mode test and
ran a **tree** scan, at exit 0.

This is not a typo nobody would make. `--history=all` is the correct
spelling on `scripts/redaction-check.mjs`, the sibling checker this seat
runs in the same sweep, where it means every ref as distinct from
`--history` meaning HEAD. This run typed it into the wrong tool on its
first attempt, which is how it was found.

**The cost, measured on the clone a seat is actually handed.** On a
shallow single-branch clone the bare `--history` refuses at exit 2,
because a truncated graph must not report clean. `--history=all` on the
same clone answered clean at exit 0. One equals sign skipped the refusal
that exists for exactly that case.

An argument the scanner does not know is exit 2 now, with the message
naming which spelling belongs to which tool. Two tests, one of them that
measurement on a real shallow clone rather than an assertion about the
message, and an eighth ground branch in the enumerator.

## 5. F55 — the scanner's own fixture, named rather than allowed

`node tools/secret-scan.mjs --history` on a complete clone exits 1 with
one hit: an `aws-access-key-id` at `tools/secret-scan-verdict.test.mjs`
line 72, in blob `ef90504d`, which is reachable from two commits and is
not what the tip of that file carries.

It is a fabricated literal that an earlier draft of that test used to
prove the verdict never prints a credential value. The test was later
rewritten and the literal removed from the tip. It is not and never was a
credential, so there is nothing to rotate.

**Recorded and deliberately not allowed.** The fix that suggests itself
is an exception in the scanner for a blob or a path it knows about. A
credential scanner with a history allowlist is how a real leak gets
hidden, and the allowlist would be added by the one actor also capable of
planting the thing it hides. So the entry stays red and this paragraph is
the control: the next run reads it here instead of re-deriving it, which
is the whole cost of the finding.
