## F1. The known history hit is already on `main`, which removes one of
## the three dispositions the engineer offered

**Severity: low as exposure, material as a correction.**

The engineer seat reported one history secret-scan hit to this seat and
named it precisely: `tools/secret-scan-verdict.test.mjs` line 72, class
`aws-access-key-id`, blob `ef90504da7db`, commit `88bb0bf3`. Every part
of that is correct. This run reproduced it on a wider graph than the
engineer had, 6412 blobs across all 268 remote refs against their 6285,
and the count is still exactly one. The working tree is clean at 2255
tracked files, 16 classes, 0 hits, and the blob at the branch tip does
not carry the value.

Two things this run establishes that the note did not.

**The value is not a credential.** It is the vendor's own published
documentation example key, the literal AWS prints in its public docs as
a sample. This was determined by comparing the flagged line against that
published literal and reporting only the boolean, so no value was read
out into this report. Rotation is therefore not the owner's action here,
which is the opposite of what this seat's charter would otherwise
require, and it is the reason this finding is not at the top of the pull
request in bold.

**The flagged commit is already an ancestor of `main`.** The note's
first disposition was a squash merge, on the reasoning that it "leaves
the flagged commit unreachable from the default branch, so the hit never
enters that history." That premise does not hold. Commit `88bb0bf3`
landed on `main` through the merge of pull request 573 at 20:47 EDT,
roughly thirteen minutes before the note was written, and
`git merge-base --is-ancestor 88bb0bf3 origin/main` is true. The blob is
in `main`'s own object graph: `main`'s history carries two blobs for that
path, the clean `edd4bb88cc3a` and the flagged `ef90504da7db`.

So the hit did not need to be let in. It is in. A squash merge of the
engineer's branch is still the right way to land that branch, and it
still puts the clean blob at the tip, but it no longer has any bearing on
whether the history scan reports a hit. That disposition was never
available, and it was the one the note recommended.

**What this run recommends instead, with the choice still the owner's.**
The second disposition, a cited baseline in the scanner, in the shape
`dep-floor.allow.json` already uses for an accepted advisory, naming this
blob and recording that the value is a vendor's published documentation
example. It is now the only option that does not rewrite the default
branch. This seat agrees with the engineer's reason for wanting one: a
permanent known hit makes the next real hit a second line in a report
that already says one, which is the same thing as having no report.

This seat recommends against the third disposition more firmly than the
engineer did. A rewrite would now have to rewrite `main`, not a side
branch, because that is where the commit sits. The engineer's objection,
that it would invalidate the ancestry checks three open pull requests
depend on, understates it.

## F2. The dead-draft sweep pattern for this seat matched one branch that
## is not this seat's

**Severity: low. Already repaired on a branch, not by this seat.**

The exo seat reported that the sweep pattern queued for this charter is a
bare substring and would hand this seat a branch it does not own. That is
correct and this run reproduced the measurement independently over all
549 pull request branches this repository has had. The bare
`sec|security` matches 26, the anchored
`^([a-z0-9-]+-)?(sec|security)/` matches 25, and the single difference is
`chair/vendor-pm-section-22`, which matches on the letters inside
"section". Anchoring loses none of this seat's own 25 branches.

One qualification this run adds, in the seat's favour and against its own
alarm. That branch is pull request 207, and it is merged. The sweep reads
open drafts only, so it would not have printed this branch today, and no
live branch of another seat was at risk at this moment. The repair is
still right, because what is wrong is the pattern rather than today's
roster of branches, and the next chair branch with those letters in it
would have been live when the sweep read it.

The fix lives in `tools/seat/branch-patterns.json` on the exo seat's
branch, one file for the whole roster, with a test that fails if any
charter's copy disagrees. This seat did not edit its own charter, which
the charter forbids, and exo did not ask it to.
