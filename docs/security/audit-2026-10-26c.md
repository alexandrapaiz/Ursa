## F23. The publish gate validates the filename and then builds every path and every public address from a different string (high, fixed in this run)

**`loadPublishable` checks the id it got from the directory listing.
`publish` writes the id that is inside the file.** They are two different
strings and nothing required them to agree.

```
loadPublishable:  SAFE_RECORD_ID.test(id)          // id = the filename
                  isForgotten(consent, id)         // id = the filename
publish:          join(recordsDir, record.task.id + '.html')
recordHref:       'records/' + record.task.id + '.html'   // into index.json
```

`record.task.id` is a field in the JSON, and `isRecordShaped` asked only
that it be a string. So one unchecked value walked past three separate
gates: the path safety check, the erasure check, and the public address.

**Measured, not reasoned about.** A record stored as
`safe-name-2026-10-26-abcdef1.json`, well-shaped in every other respect,
carrying `"id": "../../outside/escaped"`, published into a fresh output
directory alongside one good record:

- the record's **two raw files were written two directories above
  `outDir`**, as `escaped.html` and `escaped.json`, which on the `ursa ci`
  path is inside the runner's workspace rather than the artifact being
  uploaded;
- `publish` **returned success**, with the escaped paths listed in
  `written`, so a caller checking the return value saw a normal publish;
- the published set **did not contain the record it had just disclosed**,
  which is precisely the failure the module's own `.nojekyll` comment
  calls "the failure this file is least able to notice".

**Three ways this is worse than a path bug.** First, the written files are
the raw record: `files[].text`, `generations[].text` and
`conversations[].prompts[].text`, the three fields `src/types.ts`
annotates "Raw data; stays local." Second, the erasure check reached the
wrong id, so a record erased under its real id and present on disk under
another filename would have been published, which is the load-bearing
constraint in CLAUDE.md — the user can always revoke and delete — broken
at the one boundary where failing it is visible to strangers. Third, it
is reachable without a malicious user at all: a record copied between
clones is a case the file already anticipates, and on the `ursa ci` path
records arrive in a runner workspace from a repository anyone may open a
pull request against.

**Fixed by requiring the two to agree.** `saveRecord` in `src/store.ts`
writes `records/<record.task.id>.json`, so the filename and the field are
the same string for every record this product has ever written, and the
check refuses nothing a resolver can produce. Refused rather than
sanitised: rewriting an identifier to make it safe would publish a record
at an address that is not its own, and `skipped` already carries the
`unsafe-id` reason, so no type and no caller changed.

## F24. One malformed record took the whole publication down, which is the opposite of what the module promises (medium, fixed in this run)

`PublishResult.skipped` is documented as existing so that "one unreadable
file must not stop a publication of fifty good records", and
`isRecordShaped` is documented as "the fields every consumer in this file
walks". It was missing two of them. `summarize` dereferences
`record.artifact.kind` and `record.stats.generated.charsWritten`, and
neither was checked.

**Measured:** three records in one store, two of them missing `artifact`
and `stats.generated` respectively, one of them perfect. `publish` threw
`Cannot read properties of undefined (reading 'kind')` and **nothing was
written at all**, including the good record. Both fields are required and
non-optional in `src/types.ts` (`artifact: Artifact`, `stats: Stats`,
`generated` inside it), so adding them to the shape check cannot refuse a
record the type permits, which is what makes this a fix and not a
tightening.

## F25. Five regression tests, four of them proven against the pre-fix module

The property that makes a regression test more than decoration is that it
fails before the fix. Verified by stashing the fixed module, keeping the
tests, and re-running:

| Test | Pre-fix |
|---|---|
| cannot write its two files outside the output directory | **fails** |
| does not reach the disclosure manifest | **fails** |
| is refused even when the id it carries is a safe one | **fails** |
| one malformed record is skipped, not fatal | **fails** |
| still publishes every record a resolver actually wrote | passes, by design |

The fifth passes both ways on purpose. It is the no-regression guard, and
a guard that failed before the fix would mean the fix had narrowed what
publishes.

The first test reads the filesystem rather than the return value, because
the pre-fix module reported success and named the escaped paths in
`written`. A test that trusted the result would have passed against the
defect.
