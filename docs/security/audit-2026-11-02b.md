## F50 — a scan note that announces itself in the seat tag was held to five fields it does not owe

**Moderate. Ursa's own code. Fixed in this run, with four tests.**

This is the defect F49 measured its window on, and it is worth stating
separately because the repair is not where the failure text pointed.

`tools/ledger/check.mjs` was red on `main` over one block of
`docs/ideas.md`, reporting all five of pm.md §4's fields missing. The
block is a craft-scan note, and a scan note owes no fields. Its heading:

```
### 2026-11-02 (engineer, craft scan) — Letta Context Repositories: ...
```

`ENTRY_HEADING` in `tools/ledger/block-kinds.mjs` accepts and captures a
parenthesized seat tag after the date, and this seat wrote the scan
announcement into that tag. `announcesScan` tested the title only, so
the block classified as an `idea` and owed the five fields.

**Why this is the position and not the vocabulary, which matters because
the file warns against exactly the wrong version of this fix.** A run on
2026-10-26 was handed this gate red, read the same bare missing-field
message, and reported that the heading used a spelling the classifier
does not recognise. That was wrong: `SCAN_TITLE` matched the heading it
was given. The repair here changes no vocabulary. The two spellings are
`SCAN_TITLE`'s own two, and what changes is that the checker reads the
capture group it already takes.

**The strictness survives the move**, which is the part a reviewer should
check rather than take on trust. The tag is split on commas and an
element must be the whole phrase, so `(engineer, redaction scan tooling)`
announces nothing, and `COMMITS_WORK` still reclassifies a tag-announced
note that files a `- First step:`. One of the four new tests measures the
blast radius against the real file instead of asserting it from the
diff: exactly one block in `docs/ideas.md` moves, and a second one
appearing there is a reason to re-read the rule rather than to update the
number.

After the fix, `node tools/ledger/check.mjs` reports "417 blocks, clean
as far as a seat can take it", with two owner-held status violations
unchanged. The ledger suites are 126 of 126.

## F51 — the board's events route discloses neither its limit nor whether its page filled

**Low, and an increment on F47 rather than a separate fault. HQ's code,
reported only.**

pm.md §15 added `limit` and `saturated` to the messages read in October,
after `tools/autonomy.py` divided a capped read by an uncapped forge and
published an autonomy floor 14 points low. The rule it wrote down is
that a saturated page is not an answer and no ratio is published from
one. `GET /api/events` returns neither field, and a bare read returns
exactly 200 rows, which is the shape of a cap rather than of a count. So
a caller cannot tell a complete read from a truncated one even on the one
request that still answers, and will not be able to on the day the
filters are repaired. This run published no number from that route.
