## F44 — The history scan refused a shallow clone and not a single-branch one

**Severity: high. Fixed in this run. No disclosure, and the verdict it was
reporting was correct the whole time.**

`tools/ensure-full-clone.sh` treats depth and refspec as two independent
properties of an incomplete clone, repairs both, and says in its own header
that repairing one is not enough. `docs/standards/lessons.md` names it that
way twice, in L-A55 and L-A77. `tools/secret-scan.mjs --history` checked one
of them. It tested for `.git/shallow` and said nothing about
`remote.origin.fetch`, so a clone made with `--single-branch` at full depth
passed the guard, and `rev-list --objects --all` then walked one branch's
objects and printed `history: ... 0 hit(s)` at exit 0.

That is the same indistinguishable zero the file's own header refuses for
depth, arriving by the other door, in the one tool whose output is supposed
to mean nothing credential-shaped exists anywhere in this repository's
history.

**Measured both ways, not read off the code.** A throwaway repository with
an AWS-key-shaped canary on a branch other than the default:

| clone | `.git/shallow` | tool says | exit |
|---|---|---|---|
| `--single-branch`, full depth | absent | `1 blobs, 16 classes, 0 hit(s)` | 0 |
| same clone, refspec widened, nothing else changed | absent | `2 blobs, 16 classes, 1 hit(s)` | 1 |

The probe was built outside this repository with a value assembled at run
time, measured, and destroyed. Its value appears in no stream, no commit and
no file here.

**And on this repository, which is the figure that says what the hole was
worth.** The clone a seat is handed is `--single-branch`. This run's first
history scan, taken in it, walked **5,304 blobs**. After the refspec repair
alone it walked **6,532**. So **1,228 blobs, 19% of this repository's
history, were outside every `--history` result this seat has published since
2026-10-25**, and not one of those results said so. Both scans found the
same single hit, so nothing is leaked and there is nothing to rotate. What
was wrong was the coverage claim, not the verdict.

**The fix.** The guard names every fault it finds rather than the first, so a
clone that is both shallow and narrow reports both. It asks `git rev-parse
--is-shallow-repository` instead of testing for a path. It does not refuse a
repository with no `origin`, because that repository's own refs are the whole
graph and refusing it would make the test suite's canary repository
unscannable. Six new expectations; three were confirmed to fail against the
pre-fix tool and pass after.

### F44(b) — The same fail-open one level down, in the sibling checker

**Severity: low. Fixed in this run.** `scripts/redaction-check.mjs` refused a
history scan by testing for the path `.git/shallow`. In a linked worktree
`.git` is a file and the marker lives in the main git directory, so the test
is false in a worktree of a shallow clone and the refusal never fires.
Measured on a depth-1 clone with a worktree added: in the clone the path
exists and `rev-parse` says `true`; in the worktree the path does not exist,
`.git` is ASCII text, and `rev-parse` still says `true`.

The refspec half does not apply there and the comment says why: that scan
walks one named ref rather than `--all`, so the caller declares the scope and
a narrow refspec cannot quietly shrink it.

## F45 — The published history figures are unfalsifiable, and F44's fix does not reach them
